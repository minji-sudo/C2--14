# 과제 14: 힙 정렬, 퀵 정렬 및 병합 정렬의 성능 비교

## 1. 개요

이전 과제의 병합 정렬·퀵 정렬(피벗 3종)에 힙 정렬을 추가하고, 데이터 크기 n = 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000 에서 숫자 비교 횟수, 실행시간, 추가 메모리 사용량을 측정해 비교했다.

## 2. 측정 방법

| 항목 | 측정 방법 |
|---|---|
| 비교 횟수 | 데이터 값끼리 비교하는 지점마다 전역 카운터 `g_cmp++`. 반복문 인덱스·종료 조건 검사는 제외. 힙 정렬은 힙 구성 + 힙 속성 복구, 퀵 정렬은 피벗 선택(Median-of-Three의 3번 비교)까지 포함. 20회 평균 |
| 실행시간 | `clock_gettime(CLOCK_MONOTONIC)` 으로 정렬 함수 호출 직전~직후만 측정. 데이터 생성, 배열 복사, 출력 시간은 제외. 한 번만 재면 시간이 너무 짧아 오차가 커서 **20회 반복한 평균(ms)** 사용 |
| 메모리 | 아래 3장의 계산 기준으로 직접 계산 (프로파일링 도구 사용 안 함). 20회 중 최댓값 |

Random 피벗은 `rand()` 때문에 실행마다 비교 횟수와 재귀 깊이가 달라진다. 첫 실행 한 번만 쓰면 운 좋은/나쁜 한 번이 대표값이 되는 표본 편향이 생기므로,
같은 데이터로 20번 반복해서 비교 횟수는 20회 평균(반올림), 메모리는 "최대 추가 메모리"라는 정의에 맞춰 20회 중 최댓값을 사용했다. 나머지 알고리즘은 입력이 같으면 매번 같은 값이 나오므로 반복해도 결과가 같다.


## 3. 메모리 사용량 계산 기준

원본 배열 `n * sizeof(int)` 는 모든 알고리즘의 공통 비용이므로 제외하고, 정렬을 위해 추가로 필요한 메모리의 최댓값만 계산했다.

- 호출 스택 1프레임 = (매개변수 + 지역변수의 `sizeof` 합) + 복귀 주소(8B) + 이전 BP(8B)  (64비트 기준)
- 재귀 함수는 실행 중 측정한 **최대 재귀 깊이** × 프레임 크기로 계산하고, 마지막에 호출되는 리프 함수(`partition`, `merge`) 프레임을 1번 더한다.

| 알고리즘 | 계산식 |
|---|---|
| 힙 정렬 | `heap_sort` 프레임(36B) + `sift_down` 프레임(44B) = **80B** (재귀 없음, 제자리 정렬) |
| 병합 정렬 | 임시 배열 `n * 4B` + 최대 재귀 깊이 × 44B + `merge` 프레임 56B |
| 퀵 정렬 | 최대 재귀 깊이 × 40B + `partition` 프레임 48B |

## 5. 비교·분석

### 5.1 데이터 크기 증가에 따른 비교 횟수 변화

세 알고리즘 모두 n이 커질수록 비교 횟수가 `n log n` 에 가깝게 증가했다. n이 1,000에서 16,000으로 16배 커질 때 비교 횟수는 힙 약 23.6배, 병합 약 23.3배, 퀵(First) 약 23.6배로 늘었는데,
이는 `n log n` 이론 증가율(약 22.4배)과 비슷하다. 즉 데이터가 2배가 될 때 비교 횟수는 2배보다 조금 더 늘어나는 정도였다.

알고리즘 간 차이는 크기와 상관없이 일정한 비율로 유지되었다. n = 20,000 에서 병합 정렬이 260,842회로 가장 적었고(약 0.91 · n log₂n),
퀵 정렬이 약 34만 회(약 1.2 · n log₂n), 힙 정렬이 510,887회(약 1.8 · n log₂n)로 가장 많았다. 병합 정렬은 이미 정렬된 두 부분을 합치므로 한 번의 비교로 원소 하나를 확정할 수 있어서 비교 횟수가 이론 최소치에 가깝다. 
반면 힙 정렬은 `sift_down` 한 단계마다 "두 자식 중 큰 쪽 고르기"와 "부모와 비교하기"로 비교가 2번발생하고, 루트에 올린 값이 대부분 다시 맨 아래까지 내려가기 때문에 병합 정렬의 약 2배 가까운 비교가 필요했다.

### 5.2 실행시간 차이

n = 20,000 기준으로 퀵 정렬(1.82~2.05ms)이 가장 빨랐고, 병합 정렬(2.87ms)과 힙 정렬(2.94ms)이 비슷했다. 비교 횟수는 병합 정렬이 가장 적었는데도 시간은 퀵 정렬이 더 짧았다. 이유는 다음과 같이 추정했다.

- 병합 정렬은 비교는 적지만 임시 배열로 복사했다가 다시 원래 배열로 복사하는 과정에서 대입 연산이 많다.
- 퀵 정렬은 같은 배열 안에서 앞에서부터 순차적으로 접근하므로 캐시 효율이 좋고, 교환 위주라 연산이 단순하다.
- 힙 정렬은 비교 횟수가 가장 많고, `i → 2i+1` 로 인덱스가 크게 점프하면서 접근해 캐시 효율이 떨어지는 것도 영향을 줬을 것으로 보인다.
   

즉 비교 횟수가 적다고 항상 빠른 것은 아니고, 배열 복사·메모리 접근 방식 같은 상수 비용도 실행시간에 크게 영향을 준다.


### 5.3 메모리 사용량 차이

- 힙 정렬: 입력 배열 자체를 힙으로 쓰고 `sift_down`을 반복문으로 구현해서 재귀가 없다. 그래서 n과 무관하게 **80B로 고정**(O(1))이다.
- 병합 정렬: 병합 시 필요한 임시 배열 때문에 `4 · n` Byte가 필요해 n에 **선형으로 증가**한다. n = 20,000 에서 80,760B로 다른 알고리즘보다 압도적으로 크다.
  재귀 스택은 깊이가 `log₂n` 수준(약 11~16단계)이라 n = 20,000 에서는 전체의 약 1%에 불과했지만, n = 1,000 에서는 약 10%(484B/4,540B)로 작은 n일수록 비중이 컸다.
- 퀵 정렬: 임시 배열이 없고 재귀 스택만 쓴다. 최대 재귀 깊이가 약 28~38단계라 n = 20,000 에서도 약 1.2~1.6KB 정도이고, n이 20배 커지는 동안 메모리는 약 1.5배만 늘었다(`log n` 수준 증가).
  다만 이는 입력이 무작위라 깊이가 `log n` 근처로 유지된 결과이고, 피벗이 계속 나쁘게 선택되면 깊이가 n까지 커질 수 있다.

### 5.4 퀵 정렬 피벗 선택 방법에 따른 차이

이번 데이터는 무작위 정수라서 세 방식의 차이가 작았다. n = 20,000 에서 비교 횟수는 First 344,074 / Random 340,739 / Median3 344,679 로 거의 비슷했고, 시간도 1.82 / 2.00 / 2.05ms 로 큰 차이가 없었다.

세 방식의 차이가 작았던 이유는 입력이 완전 무작위이기 때문이다. 

반대로 입력이 이미 정렬되었거나 역순이면 이 가정이 깨진다. 
첫 원소가 항상 최솟값(또는 최댓값)이라 분할이 매번 `0 : n-1` 로 치우치므로 First만 `O(n²)` 으로 급격히 느려진다. 재귀 깊이도 `log n` 이 아니라 n까지 늘어나므로 스택 메모리가 같이 폭증한다. 
이 프로그램의 First 프레임(40B) 기준으로 계산하면 n = 20,000 에서 약 800KB(40B × 20,000) 이고, n이 더 커지면 스택 오버플로까지 날 수 있다. 


- First: 선택 비용이 없어 가장 단순하고 빠르다. 하지만 이미 정렬되었거나 역순인 데이터에서는 피벗이 항상 최소·최대가 되어 `O(n²)` 로 느려지고 재귀 깊이도 n까지 늘어날 수 있다.
- Random: 입력 순서에 상관없이 평균적으로 좋은 분할을 기대할 수 있어 최악의 경우를 피하는 데 유리하다.
- Median-of-Three: 분할이 극단적으로 치우칠 확률을 줄여 주지만 호출마다 비교 3번이 추가된다. 이번 실험에서는 First 대비 비교 횟수 감소가 뚜렷하게 나타나지 않았디
 재귀 깊이가 비교적 얕아 메모리는 가장 적은 편이었다(n=20,000 에서 1,168B).

정리하면, **무작위 데이터에서는 어떤 방식을 써도 성능이 비슷하지만, 정렬된 데이터 등 입력이 편향될 수 있는 상황에서는 Random 또는 Median-of-Three가 안전**하다고 해석했다. (정렬된 입력에 대한 실험은 이번 과제 범위에 포함하지 않아 직접 측정하지는 않았다.)

### 5.5 시간 복잡도 및 공간 복잡도 비교

| 알고리즘 | 최선 | 평균 | 최악 | 공간 복잡도 | 안정성 |
|---|---|---|---|---|---|
| 힙 정렬 | O(n log n) | O(n log n) | O(n log n) | O(1) | 불안정 |
| 병합 정렬 | O(n log n) | O(n log n) | O(n log n) | O(n) | 안정 |
| 퀵 정렬 | O(n log n) | O(n log n) | O(n²) | O(log n) (최악 O(n)) | 불안정 |

실험 결과는 이론과 대체로 일치했다. 시간은 세 알고리즘 모두 평균적으로 `n log n` 으로 증가했고, 메모리는 힙(상수) < 퀵(로그) < 병합(선형) 순으로 증가했다.

## 6. 결론

- 비교 횟수는 병합 정렬이 가장 적고 힙 정렬이 가장 많았다.
- 실행시간은 이번 실험에서 퀵 정렬이 가장 빨랐다. 비교 횟수 외에 배열 복사량과 캐시 효율 같은 상수 비용이 영향을 주었다고 판단했다.
- 메모리는 제자리 정렬인 힙 정렬이 80B 고정으로 가장 작고, 임시 배열이 필요한 병합 정렬이 가장 컸다.
- 최악의 경우를 보장해야 하고 메모리가 부족하면 힙 정렬, 안정 정렬이 필요하면 병합 정렬, 평균 속도가 중요하면 퀵 정렬이 적합하다고 정리할 수 있다.
